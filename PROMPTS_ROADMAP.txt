[STEP 1] 핵심 지표 및 와이코프 스캐너 엔진 구축
================================================================================

--------------------------------------------------------------------------------
▼ [AI 전달용 프롬프트 (이 아래 내용만 복사하세요)]
--------------------------------------------------------------------------------
안녕! 이 프로젝트는 리처드 와이코프 매집 이론과 서브섹터 자금 흐름을 결합한 퀀트 주식 시스템(Whykoff)이야.

이미 프로젝트의 뼈대와 핵심 규칙이 완벽히 준비되어 있어:
1. `agent.md`: 레이어드 아키텍처 규칙과 퀀트 거버넌스 원칙
2. `CORE_LOGIC_SPECS.md`: 와이코프 6단계 매집 공식, 스윗스팟 별점(68~78점), 포지션 상태 머신 명세
3. `evaluator_agent.md`: Gemini AI 리스크 매니저 종합 평가 프롬프트 규격
4. `schema.sql` & `core/`: DB 연결 풀, 모델, 설정 모듈 (기존 18만 건의 PostgreSQL 데이터와 연동 검증 완료)

우리는 코드가 엉키지 않도록 단계별(Step-by-Step)로 하나씩 구현하고 실제 DB 데이터로 테스트하며 조립해 나갈 거야.

먼저 위 가이드 문서들과 `core/` 내부 코드를 꼼꼼히 읽고 구조를 파악해 줘.
파악이 끝나면 **[1단계 작업]**으로 다음 모듈을 순수 함수 형태로 작성해 줘:
- `engine/indicators.py`: RSI, MACD, MFI, OBV, ATR, Volume Profile POC(최대 매물대) 연산
- `engine/wyckoff_scanner.py`: `CORE_LOGIC_SPECS.md`의 6단계 매집 알고리즘 및 '지표 원점수(0~100) + 스윗스팟 별점(1~5성)' 산출 로직

작성 후 실제 DB(`ohlcv_daily`)에서 데이터 1종목을 불러와 정상 작동하는지 테스트 스크립트 실행 결과까지 보여줘.
--------------------------------------------------------------------------------

[💡 사용자 검증 포인트 (복사하지 마세요)]
1. `engine/indicators.py`에서 지표 연산 시 직전 완성봉(`iloc[-2]`)을 기준으로 판별하여 지표 리페인팅(Repainting)을 방지했는지 확인.
2. `engine/wyckoff_scanner.py`에서 68~78점 구간 종목에 대해 스윗스팟 5성(⭐⭐⭐⭐⭐)이 정상 부여되는지 확인.
3. 85점 이상 과열 종목에 2성(추격 금지 경고) 플래그가 정상 작동하는지 확인.
4. 테스트 실행 시 DB 오류 없이 점수와 SL/TP1/TP2 가격이 정상 출력되는지 확인.



================================================================================
[STEP 2] 챔피언-챌린저 (Champion-Challenger) 백테스트 게이트 구축
================================================================================

--------------------------------------------------------------------------------
▼ [AI 전달용 프롬프트 (이 아래 내용만 복사하세요)]
--------------------------------------------------------------------------------
1단계 엔진 구현 고마워! 

이제 `agent.md`와 `CORE_LOGIC_SPECS.md` 섹션 5에 명시된 **[2단계: 백테스트 검증 게이트]**를 구축할 차례야.
- 모듈 위치: `engine/backtester.py`
- 핵심 요구사항:
  1. DB의 `ohlcv_daily` 과거 1년치(약 16만 건) 데이터를 기반으로 와이코프 매집 전략 시뮬레이션 실행.
  2. 3대 핵심 벤치마크 산출: 승률(Win Rate, 55%+ 기준), 손익비(Profit Factor, 2.0+ 기준), 기대값(Expectancy, >0).
  3. 백테스트 결과를 `schema.sql`의 `strategy_benchmarks` 테이블에 기록하는 함수 구현.
  4. 기존 기준값(Champion)과 신규 튜닝값(Challenger)의 성과를 비교하여 기대값 우위일 때만 승격하는 CLI 비교 함수 제공.

모듈 작성 후, 전체 종목 중 10개 종목을 샘플링하여 실제로 백테스트를 돌려보고 통계 결과가 콘솔에 출력되는 모습을 보여줘.
--------------------------------------------------------------------------------

[💡 사용자 검증 포인트 (복사하지 마세요)]
1. 백테스트 엔진이 미래 참조 편향(Look-ahead bias) 없이 당일 종가 매수 / 익일 시가 매수 원칙을 지켰는지 확인.
2. 익절(TP1 +20%, TP2 +50%)과 손절(박스 하단 -2%) 및 최대 보유일(20일) 규칙이 정확히 시뮬레이션되는지 확인.
3. `strategy_benchmarks` 테이블에 테스트 결과가 에러 없이 INSERT 되는지 확인.



================================================================================
[STEP 3] 스냅샷 기록 & 단일 포지션 라이프사이클 트래커 구축
================================================================================

--------------------------------------------------------------------------------
▼ [AI 전달용 프롬프트 (이 아래 내용만 복사하세요)]
--------------------------------------------------------------------------------
백테스트 게이트 확인 완료!

이제 스캔된 종목의 중복 문제를 방지하고 실전 성과를 1:1로 추적하기 위한 **[3단계: 포지션 트래커]**를 구축해 줘.
- 모듈 위치: `services/trade_tracker.py`
- `CORE_LOGIC_SPECS.md` 섹션 6의 상태 머신 규칙 철저 준수:
  1. `record_scan_snapshots(results)`: 스캔된 모든 종목의 점수/별점/지표를 `scan_snapshots`에 무조건 기록 (일자별 빌드업 히스토리).
  2. `process_active_trades(results)`: 
     - 해당 종목이 이미 `active_trades`에 `status = 'OPEN'` 상태로 존재하면: 새 거래를 생성하지 않고 `reconfirmed_count`만 +1 증가.
     - `OPEN` 포지션이 없다면: 신규 포지션(`status = 'OPEN'`) 생성 및 최초 진입가/SL/TP 고정.
  3. `update_open_positions_daily()`:
     - 매일 장마감 후 최신 종가로 OPEN 포지션들의 현재 수익률(PnL %), 최대 유리 수익(MFE), 최대 불리 낙폭(MAE) 갱신.
     - 주가가 TP1(+20%), TP2(+50%), SL(손절선), 또는 20영업일 초과 시 `CLOSED` 처리 및 실현손익 확정.

모듈 작성 후 가상 스캔 결과를 넣어 `scan_snapshots`와 `active_trades`가 중복 없이 깔끔하게 처리되는지 단위 테스트 결과를 보여줘.
--------------------------------------------------------------------------------

[💡 사용자 검증 포인트 (복사하지 마세요)]
1. 동일 종목을 3일 연속 스캔 테스트했을 때, `scan_snapshots`에는 3개 행이 쌓이고, `active_trades`에는 단 1개의 포지션만 유지되는지 확인 (매우 중요!).
2. 최초 진입가와 손절선이 변경되지 않고 고정되어 정산의 왜곡이 없는지 확인.

[STEP 4] AI 리스크 매니저 종합 평가 에이전트 구축
================================================================================

--------------------------------------------------------------------------------
▼ [AI 전달용 프롬프트 (이 아래 내용만 복사하세요)]
--------------------------------------------------------------------------------
포지션 트래커 완벽해!

이제 와이코프 스캐너가 발굴한 종목을 헤지펀드 리스크 매니저 관점에서 최종 판정하는 **[4단계: AI 종합 평가 에이전트]**를 만들 차례야.
- 모듈 위치: `services/llm_evaluator.py`
- `evaluator_agent.md`의 프롬프트 규격 엄격 준수:
  1. 입력 데이터 취합: 스캔 결과(점수/별점/POC/SL/TP) + 소속 서브섹터(SOXX, IGV, CRYPTO 등) 동향 + 매크로(VIX, 지수) + 최근 뉴스 요약.
  2. 4대 평가 축 크로스체크: 기술적 순도, 서브섹터 자금 일치, 거시 리스크, 개별 재료/어닝 리스크.
  3. Gemini API(`core.config.settings.gemini`)를 호출하여 최종 등급(A/B/C) 및 트레이딩 가이드 리포트 생성.
  4. 텔레그램 친화적 HTML 태그(`<b>`, `<code>`)만 사용하고 `<p>`, `<br>` 등 파싱 에러 태그 철저 정제.
  5. 평가 결과를 `scan_snapshots`의 `ai_rating`, `ai_verdict`에 저장.

모듈 작성 후 샘플 1개 종목에 대해 실제로 Gemini API를 호출하여 생성된 최종 리포트 출력을 보여줘.
--------------------------------------------------------------------------------

[💡 사용자 검증 포인트 (복사하지 마세요)]
1. Gemini API 키 연동 오류 없이 정상적으로 리포트가 생성되는지 확인.
2. AI가 단순 기사 요약이 아니라 "A/B/C 등급"과 "실제 권장 비중/행동 지침"을 명확히 주는지 확인.
3. 텔레그램 전송 시 태그 에러가 발생하지 않도록 `<br>`, `<p>` 태그가 제거되었는지 확인.

[STEP 5] 장후마감 리포트 & 텔레그램 봇 및 스케줄러 통합

▼ [AI 전달용 프롬프트 (이 아래 내용만 복사하세요)]
--------------------------------------------------------------------------------
AI 평가 에이전트까지 완료되었어!

이제 모든 모듈을 통합하여 매일 자동으로 시장을 감시하고 텔레그램으로 알려주는 **[5단계: 최종 서비스 통합]**을 진행해 줘.
- 모듈 위치:
  1. `services/briefing_service.py`: 
     - `CORE_LOGIC_SPECS.md` 섹션 7 규격에 맞춘 [장후마감 리포트] 생성기.
     - **보유 포지션 조기 경보**: OPEN 포지션의 '진입 점수 vs 당일 점수 델타' 추적 (-10점 급락 또는 POC 이탈 시 경고 태그).
     - **누적 성과 대시보드**: 최근 60일 롤링 완료 거래 수, 승률(%), 손익비(PF), 평균 보유일 집계.
  2. `services/telegram_bot.py`:
     - `/scan [서브섹터]`: 특정 서브섹터(SOXX, IGV, CRYPTO 등) 지정 와이코프 즉시 스캔 커맨드.
     - `/portfolio`: 현재 추적 중인 OPEN 포지션 현황 조회.
     - 브리핑 및 스캔 알림 발송 핸들러.
  3. `services/scheduler.py`: 미국 증시 개장일 체크 후 장전 프리마켓 및 장마감 브리핑 자동 트리거.
  4. `main.py`: 시스템 전체 데몬 진입점.

모듈 작성 후 장후마감 리포트 메시지를 생성하여 콘솔 및 텔레그램으로 테스트 발송한 결과를 보여줘.
--------------------------------------------------------------------------------

[💡 사용자 검증 포인트 (복사하지 마세요)]
1. 장후마감 리포트에 보유 포지션의 '점수 변화(Score Delta)'와 '60일 성과 대시보드'가 깔끔하게 출력되는지 확인.
2. 텔레그램 봇 토큰 및 Chat ID로 실제 메시지가 도착하는지 확인.
3. `/scan SOXX` 같은 명령어 입력 시 반도체 소속 종목 풀 안에서만 스캔이 동작하는지 확인.
